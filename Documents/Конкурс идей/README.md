# Конкурс идей: план и спецификации задач

Эта папка — рабочее место для планирования разработки: поэтапный план, таблица задач со статусами
и спецификация на каждую задачу. Код здесь не хранится. Общие правила проекта — [CLAUDE.md](../../CLAUDE.md).

## Что где лежит

| Файл | Назначение |
|---|---|
| [TODO.md](TODO.md) | Цель и границы MVP, этапы, таблица всех задач, зависимости, открытые вопросы. **Единственный источник статусов** |
| [specs/](specs/) | Спецификация задачи `IC-NNN.md` — предмет обсуждения и ревью |
| [process/](process/) | Исходные отчёты агентов Senior Analyst и Senior AI Engineer по раундам планирования |

## Формат идентификаторов

`IC-NNN Название коммита` — трёхзначный номер и название в форме «глагол + конкретное изменение».

- Одно и то же название используется в TODO.md, в заголовке спецификации и как заголовок коммита (и MR).
- Номер не меняется после присвоения; при перестановке задач номера не пересчитываются.
- Новые задачи получают следующий свободный номер; номера отменённых задач не переиспользуются (статус «Отменена»).
- Названия «Доработки», «Разное», «Исправления» запрещены.

## Статусы (только в TODO.md)

| Статус | Когда ставится |
|---|---|
| Черновик | Спецификация составлена, но не обсуждалась |
| Готова к разработке | Владелец согласовал спецификацию; открытых вопросов, блокирующих работу, нет |
| В работе | Создана ветка задачи |
| Заблокирована | Ждёт ответа владельца или другой задачи (причина — в спецификации) |
| Готово | MR смержен владельцем, CI зелёный, критерии приёмки отмечены |
| Отменена | Задача больше не нужна (причина — в спецификации) |

Созданная документация не делает задачу выполненной: «Готово» ставится только после мержа кода.

## Как обсуждаем и согласуем спецификации

1. Обсуждение идёт по одной спецификации; начинаем с той, что указана первой в TODO.md.
2. Пункты с пометкой «Требует обсуждения» — вопросы к владельцу; предложения агентов не считаются требованиями, пока не согласованы.
3. Принятое решение записывается в раздел «Принятые решения по результатам обсуждения» этой спецификации с датой, а при изменении архитектуры — ещё и в CLAUDE.md §17. Существенные решения не остаются только в переписке.
4. Если решение меняет другие задачи, в том же изменении правятся их спецификации и строки TODO.md.
5. После согласования статус в TODO.md меняется на «Готова к разработке».
6. Реализация: ветка на задачу, коммит с названием задачи, MR в GitHub, мерж — владелец (CLAUDE.md §16 п. 8). Перед MR — самопроверка Senior (CLAUDE.md §6.5).

## 5. Технические вопросы, блокирующие детализацию

1. **Граф модулей §4.2** (П-1/П-2/П-3): (а) кто собирает список идей фазы голосования с `my_vote` — `vote.service` или `idea` через порт; (б) `reminder` над `vote`; (в) аудиторию событий вычисляет публикующий сервис, `realtime` только рассылает. Блокирует import-linter, IC-017, IC-020, IC-037, IC-038.
2. **Где доказывается Docker-часть**: в контейнере агента нет демона Docker. Принимаем ли: integration — локальный PG 16 агента + CI; `make up`, `check_singleton.sh`, e2e — только GitHub Actions (и вручную на Mac)? Есть ли на Mac Docker Desktop, uv, Node 22?
3. **Процесс MR**: мелкие задачи (S) одним MR или строго по одной; обязателен ли зелёный CI до мержа; разрешены ли стек-ветки (MR на ветку предыдущего MR) — от этого зависит, можно ли вести политики/frontend параллельно и как разрешать конфликты линейных миграций Alembic.
4. **Lock → миграции**: согласен ли владелец на python-лаунчер (lock берётся в процессе, затем `alembic.command.upgrade`, затем `uvicorn.Server`) вместо shell-entrypoint — это меняет runbook и §7.4.
5. **Синхронный тик в e2e** (`POST /api/__test__/clock` после сдвига выполняет тик) — нужно закрепить в §8.2, иначе e2e писем либо ждут 15 с, либо флейкуют.
6. **`phase_changed`**: публиковать из тика финализации или удалить тип события (П-12).

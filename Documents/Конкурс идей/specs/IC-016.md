## Принятые решения по результатам обсуждения

Решения реализации (2026-10-22; координатор по поручению владельца, на согласование в MR). Спецификация с владельцем отдельно не обсуждалась; открытый вопрос о поясе дедлайнов решён как допущение, ждёт подтверждения.

- Маршруты: `/login`, `/register` (публичные), `/` — список конкурсов под `RequireAuth` (сессия — запрос `GET /api/auth/me`; 401 — «не вошёл», любая другая ошибка — сообщение с кнопкой «Повторить», а не уход на вход). Страница конкурса `/contests/:id` — IC-017; ссылки в списке уже ведут на неё и до IC-017 открывают «Страница не найдена».
- Регистрация сразу открывает сессию (так отвечает backend, IC-008): отдельного входа после неё нет. После входа и регистрации — переход на адрес, с которого пользователя увели.
- Ошибки: `invalid_credentials`, `too_many_attempts` (с временем из `Retry-After`), 503, 500, обрыв сети — над формой; `email_taken`, `email_domain_not_allowed` — у поля e-mail; `deadlines_order` — у поля голосования, `deadline_in_past` — у поля приёма идей; `errors[]` из 422 — у своих полей. Клиентские проверки (пустые поля, пароль 10–128, тема ≤ 200, описание ≤ 10 000, порядок дедлайнов, несуществующая дата) только экономят запрос: решает сервер.
- Дедлайны вводятся в `datetime-local` в поясе браузера и уходят как ISO 8601 со смещением («2026-10-24T18:00:00+03:00»); время, которого нет (31 февраля, пропавший час перехода на летнее время), отклоняется до отправки. В списке время показывается в поясе браузера. `DISPLAY_TZ` — только для писем.
- Кнопка и форма создания конкурса видны только организатору (`role === "organizer"` из `/api/auth/me`), права всё равно проверяет сервер (403 показывается над формой).
- Список: страницы по 20 (`limit`/`offset`, `total` из ответа), пустое состояние различает сотрудника и организатора, страница за концом списка возвращает к началу. Поля списка (`id`, `topic`, `submission_deadline`, `voting_deadline`, `phase`) — предположение по CLAUDE.md §8.2; после вливания IC-010 типы берутся из OpenAPI (см. IC-015) и расхождение полей проявится как ошибка `tsc`.
- Выход очищает кэш запросов прежнего пользователя (кроме самой сессии).
- Тесты: Vitest + MSW — приложение целиком по маршрутам (вход, регистрация, выход, защита маршрутов, потеря сессии, список, пустые состояния, пагинация, создание, все ветки ошибок 401/403/409/422/429/500/503/сеть).

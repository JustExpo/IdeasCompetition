# IC-011 Реализовать подачу идей с идемпотентным повтором и лимитами

| Поле | Значение |
|---|---|
| Этап | Э3. Backend сквозного сценария |
| Приоритет | Высокий |
| MVP | Да |
| Статус | см. [TODO.md](../TODO.md) — единственный источник статусов |
| Ожидаемый результат | `POST /api/contests/{id}/ideas`: 201, повтор с тем же ключом — 200; закрытие по дедлайну, лимиты 20/1000 |

## Цель и ценность

Ф2, П2: идея после закрытия не принимается, даже если страница открыта; повтор после таймаута не создаёт дубль.

## Контекст

Порядок шагов задан в CLAUDE.md §7.2; модели `Idea`, `IdeaContent` и ошибки готовы.

## Что входит в задачу

- `idea/dao` и миграция (uuid, FK RESTRICT, CHECK длин, `UNIQUE(author_id, client_request_id)`)
- `idea/service.submit_idea`: поиск по ключу до проверки фазы, `request_hash` с `contest_id`, `contest FOR SHARE`, `now` после блокировки, лимиты, `ON CONFLICT DO NOTHING`
- Заготовка `EventPublisher` с пустой реализацией (подменяется в IC-024)

- Список идей и правка (IC-012)

## Функциональные требования

- Организатор → 403 `organizer_cannot_participate`
- На `d` и `d+1µs` → 409 `submission_closed`
- Тот же ключ с другим телом → 422 `idempotency_key_reused`

## Технические ограничения и затрагиваемые компоненты

- `idea/*`, миграция
- Общие правила: CLAUDE.md §4 (модули и слои), §6 (стиль), §14 (Definition of Done).

## Пограничные случаи и обработка ошибок

- Повтор после дедлайна с тем же ключом → 200 с принятой идеей
- 21-я идея автора → 409
- NUL и суррогаты → 422

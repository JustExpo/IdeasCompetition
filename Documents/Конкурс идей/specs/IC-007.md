| Поле | Значение |
|---|---|
| Этап | Э2. Пользователи и вход |
| Приоритет | Высокий |
| MVP | Да |
| Статус | см. [TODO.md](../TODO.md) — единственный источник статусов |
| Ожидаемый результат | Таблицы users и sessions; Argon2id; организатор создаётся из env; `POST /api/auth/login`, `logout`, `GET /api/auth/me`; политики authenticated/organizer/employee |

## Цель и ценность

Каждый запрос знает действующее лицо (`Actor`), права проверяются на сервере (О5, §9.1).

## Контекст

Модели `User`, `Session`, `Actor` и ошибки уже есть. CLAUDE.md §9.1 задаёт параметры Argon2id, cookie и срок сессии 7 дней.

## Что входит в задачу

- `user/dao`, `auth/dao`, миграция (`UNIQUE(lower(email))`, `token_hash` UNIQUE, FK CASCADE)
- `auth/service`: Argon2id (OWASP, семафор 4, фиктивный хэш для неизвестного e-mail, NFKC, 10–128), создание и отзыв сессии, `resolve_actor` без кэша
- `user/service`: идемпотентное создание организатора из `ORGANIZER_*`; каркас `app/cli.py` с `create-organizer`
- `auth/controller`: login, logout, me; cookie `sid` HttpOnly, SameSite=Lax

## Функциональные требования

- Неизвестный e-mail и неверный пароль дают одинаковый ответ 401 `invalid_credentials`
- Деактивация пользователя действует со следующего запроса
- Каждый вход выдаёт новый токен

## Технические ограничения и затрагиваемые компоненты

- `user/*`, `auth/*`, `app/cli.py`, миграция
- Общие правила: CLAUDE.md §4 (модули и слои), §6 (стиль), §14 (Definition of Done).

## Пограничные случаи и обработка ошибок

- Истёкшая сессия на границе `expires_at`
- Отозванная сессия
- Пароль 9/10/128/129 символов

## Критерии приёмки

- [ ] Api: 401 без сессии, с истёкшей и отозванной
- [ ] Int: повторный старт не дублирует организатора
- [ ] Int: 10 одновременных входов не превышают семафор
- [ ] Cookie без `Secure` только в dev
- [ ] Самопроверка Senior по CLAUDE.md §6.5 записана в `docs/code-review/`; README «Состояние проекта», CLAUDE.md §17/§18 и `docs/prompts.md` обновлены; изменения приходят через MR (§16 п. 8)

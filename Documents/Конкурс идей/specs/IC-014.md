## Цель и ценность

Ф4, Ф5, П8, П10: результаты открываются ровно в `voting_deadline`, организатор видит счётчики и текущий рейтинг.

## Контекст

Ранжирование `rank_ideas` готово. Результаты не хранятся (§7.1), финализация для писем — в IC-020.

## Что входит в задачу

- `vote/dao.count_votes_by_idea`
- `result/service.get_results` — одна функция для API, дашборда и писем
- Дашборд: `ideas_count`, `voters_count` (люди с текущими голосами — допущение), `results[]` без авторов до финала
- Integration-тест `test_full_contest_cycle` (организатор → два сотрудника → подача → сдвиг часов → голоса → результаты с авторами)

## Принятые решения по результатам обсуждения

- `GET /api/contests/{id}/results`: 404 (нет конкурса) → 403 `results_not_published` (сотрудник до финала); организатор видит места без авторов, после финала — с авторами (схема по `status`).
- `GET /api/organizer/contests/{id}/dashboard`: `ideas_count`, `voters_count`, `results[]` всегда без авторов; `voters_count` — люди с текущими голосами за идеи конкурса (допущение, ждёт подтверждения владельца).
- Подсчёт — одна функция `result.service.get_results` (COUNT … GROUP BY при каждом запросе); те же места будут у финализации и писем.
- Реализовано в стори 2 (ветка `feature/story-2-voting-results`); решения ждут ревью владельца в MR.

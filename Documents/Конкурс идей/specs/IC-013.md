# IC-013 Реализовать голосование, отзыв голоса и удаление идеи

| Поле | Значение |
|---|---|
| Этап | Э3. Backend сквозного сценария |
| Приоритет | Высокий |
| MVP | Да |
| Статус | см. [TODO.md](../TODO.md) — единственный источник статусов |
| Ожидаемый результат | `PUT`/`DELETE /api/ideas/{id}/vote` (204); `DELETE /api/ideas/{id}` с каскадом голосов; `my_vote` в списке идей |

## Цель и ценность

П4–П6, П11: один голос на идею при любом числе вкладок, отзыв до закрытия, удалённая идея исчезает вместе с голосами.

## Контекст

Порядок проверок 404 → 403 → 409 (§7.2); PK `votes(idea_id, voter_id)` и `ON DELETE CASCADE` (Р5).

## Что входит в задачу

- `vote/dao` и миграция
- `vote/service.cast_vote` / `withdraw_vote`
- `idea/service.delete_idea` (409 `idea_locked` в финале)
- `my_vote` в списке фазы голосования (по графу из IC-001)

## За пределами задачи

- Событие `idea_deleted` (IC-024)

## Зависимости

- Зависит от: [IC-012 Реализовать список идей по фазам и правку идеи](IC-012.md)
- Блокирует: [IC-014](IC-014.md), [IC-023](IC-023.md), [IC-024](IC-024.md)

## Функциональные требования

- За свою идею → 403 `own_idea_vote`
- После закрытия → 409 `voting_closed`
- Повторный DELETE голоса → 204

## Технические ограничения и затрагиваемые компоненты

- `vote/*`, `idea/service`, миграция
- Общие правила: CLAUDE.md §4 (модули и слои), §6 (стиль), §14 (Definition of Done).

## Пограничные случаи и обработка ошибок

- 20 параллельных PUT → одна строка
- Удаление ‖ голос → нет «сиротских» голосов, голос получает 404
- Автор без идей голосует

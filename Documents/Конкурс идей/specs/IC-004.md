## Цель и ценность

Каждый будущий маршрут сразу получает единый формат ошибок, политику доступа и защиту от CSRF (§8.1, §9.2, §9.3).

## Контекст

CLAUDE.md §8.1 задаёт формат ошибок и коды, §9.2 — default deny и allow-list публичных маршрутов, §9.3 — проверку Origin.

## Что входит в задачу

- `app/main.py::create_app` (собирается без БД)
- `app/core/http_errors.py`: `AppError` → problem+json, переупаковка 422 FastAPI, 500 `internal_error` без деталей
- Middleware: `X-Request-ID`, тело ≤ 64 КБ (413), не-JSON (415), неверный JSON (400), `Cache-Control: no-store`, заголовки безопасности
- Механизм объявления политики маршрута и тест, перечисляющий `app.routes`
- Проверка `Origin` ∈ `ALLOWED_ORIGINS` для POST/PUT/PATCH/DELETE
- Временный `/api/health` = 200 (без БД)

## Функциональные требования

- Ответ любой ошибки содержит `code`, `title`, `status`, `request_id`
- Нет `Origin` у изменяющего запроса → 403

- Стек и SQL не попадают в ответ 500

# Конкурс идей

Сервис внутренних конкурсов идей для компании: сотрудники подают идеи, потом все голосуют,
потом объявляется победитель. Конкурс идёт раундами по расписанию.
Тестовое задание, «Задание 7. Конкурс идей». Архитектура, правила разработки и все решения — в [CLAUDE.md](CLAUDE.md).

## Репозиторий

GitHub: https://github.com/JustExpo/IdeasCompetition

## Чем делали

Проект делается вместе с AI-агентом **Claude Code** на модели **Claude Opus 5.5** (стори 1–6 с участием Claude Sonnet 5.5; модель указана в футере каждого коммита). Агент работает прямо
с папкой проекта и запускает тесты, поэтому работоспособность будет доказываться прогоном тестов, а большой контекст
модели позволяет сверять каждое решение с ТЗ. Архитектуру разбирали три субагента Claude Code
(архитектура, безопасность, данные и эксплуатация) в три раунда взаимного ревью — [docs/architecture-review.md](docs/architecture-review.md).

## Требования

Docker Desktop с Compose ≥ 2.20. Для разработки без контейнера
приложения — `uv` (Python 3.12) и Node.js 22 LTS. Подробно — [CLAUDE.md, §11](CLAUDE.md).

## Запуск

```
make up      # создаст .env из .env.example, соберёт образ, поднимет app + db + mailpit
make down    # остановит контейнеры, данные (volume pgdata) сохранятся
make logs    # логи приложения
```

После `make up`: `http://127.0.0.1:8000` (интерфейс: вход, регистрация, список конкурсов), `http://127.0.0.1:8000/api/health` и
`http://127.0.0.1:8025` (письма в Mailpit). Организатор создаётся при первом запуске из `ORGANIZER_EMAIL` / `ORGANIZER_PASSWORD`
(для разработки — заглушки из `.env.example`: `organizer@example.com` / `dev-only-change-me-organizer`); сотрудники регистрируются сами
с адресом из `ALLOWED_EMAIL_DOMAINS` (по умолчанию `example.com`). `make help` — список команд. Эксплуатация и диагностика —
[docs/runbook.md](docs/runbook.md).

Проверки: `make check` (линтеры, типы, границы модулей), `make test-unit`, `make test-int` (нужен `make up`), `make test-contract`.
`make e2e` — сценарии в настоящем браузере (Playwright): на время прогона тот же контейнер `app` переходит в режим e2e (отдельная БД
`ideas_e2e`, тестовые часы), потом сам возвращается в режим dev; нужны Node.js 22 и `npx playwright install chromium` в `e2e/`.
`scripts/check_singleton.sh` проверяет, что контейнер приложения один.

## Принятые толкования ТЗ

- «Сразу» и «без обновления страницы» — не дольше 2 секунд.
- «Не участвовал в раунде» — по текущему состоянию: нет своих идей в конкурсе / нет текущих голосов.
- «Все участники» финального письма — авторы текущих идей и проголосовавшие. Победителю приходит «Вы победили», авторам остальных идей — «Ваша идея не прошла», тем, кто только голосовал, — итоги конкурса.
- Организатор не подаёт идеи и не голосует; до финала видит результаты без авторов.
- При равенстве голосов побеждает идея, поданная раньше; при нуле голосов у всех — тоже самая ранняя.

## Известные ограничения (честно)

- Счётчики попыток входа и регистрации хранятся в памяти процесса и сбрасываются при перезапуске; адрес клиента берётся из соединения, заголовкам прокси не верим.
- Нет подтверждения e-mail: можно зарегистрировать несколько аккаунтов на разрешённом домене.
- Письма доставляются «как минимум один раз»: при сбое в узкое окно возможен дубль письма.
- Один контейнер приложения: перезапуск означает простой 5–15 секунд.
- Сигналы реального времени не гарантируют доставку: при обрыве сокета события теряются, страница после переподключения перечитывает данные сама. Смена фазы по времени сигналом не приходит — страница перечитывает данные в момент дедлайна по серверному времени.
- Лимиты 20 идей на автора и 1000 на конкурс — мягкие: при одновременных записях возможно превышение на единицы.
- Часы e2e идут только вперёд; во время `make e2e` рабочее приложение недоступно, а по окончании возвращается в режим dev с прежней БД.
- Сессии создаются без подтверждения e-mail; дедлайны конкурса после создания не меняются.
- Mailpit — заглушка: работа с реальным почтовым провайдером не проверяется.

## Следующим заходом

- Вход через корпоративный SSO вместо паролей; подтверждение e-mail и восстановление доступа.
- Изменение дедлайнов конкурса (нужен пересмотр ключа напоминаний).
- Бэкап и проверка восстановления БД; команды оператора (сброс пароля, отзыв сессий, статус); очистка устаревших сессий и тел писем; демо-данные. Не вошли: по решению владельца делаем рабочий прототип по ТЗ.
- Перемешивание порядка идей для каждого пользователя.
- Сбор метрик и оповещения; выкладка в прод (план — [docs/runbook.md §7](docs/runbook.md)).

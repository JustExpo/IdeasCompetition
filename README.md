## 1. Что это

Сервис внутренних конкурсов идей для компании.

- Организатор создаёт конкурс: тема, срок приёма идей и срок голосования.
- Сотрудники подают идеи (пока приём открыт, чужих идей не видно), потом голосуют за идеи, не зная авторов, — за свою голосовать нельзя.
- Когда голосование закрывается, объявляется победитель, раскрываются авторы, всем участникам уходят письма.
- Организатор в любой момент видит, сколько идей подано, сколько человек проголосовало и текущие результаты. Страницы обновляются сами, без перезагрузки.

## 2. Что нужно установить

| Что | Зачем | Как проверить, что установлено |
|---|---|---|
| Docker Desktop (Compose 2.20 или новее) | Запустить сайт, базу данных и почтовую заглушку. **Достаточно только его**, чтобы пользоваться проектом | Откройте Docker Desktop, дождитесь «Engine running». В терминале: `docker --version` и `docker compose version` |
| `make` | Короткие команды (`make up`). На macOS и Linux обычно уже есть | `make --version` |
| Node.js 22 | Только для проверок (`make check`, `make test-unit`, `make e2e`) | `node --version` (должно начинаться с `v22`) |
| `uv` (ставит Python 3.12) | Только для проверок backend | `uv --version` |

Свободные порты на вашем компьютере: 8000 (сайт), 8025 (почта), 5433 (база данных, нужна только проверкам).

## 3. Запуск и остановка

Откройте терминал в папке проекта.

```
make up      # первый запуск занимает несколько минут: собирается образ
```

Когда в терминале появятся адреса, откройте в браузере **http://127.0.0.1:8000**. Адрес **http://localhost:8000** тоже работает (в режиме dev).
Письма, которые отправляет сервис, смотрите на **http://127.0.0.1:8025** (Mailpit — «почтовый ящик» для проверки, настоящие письма никуда не уходят).

| Команда | Что делает |
|---|---|
| `make up` | Запускает всё. Если `.env` нет, создаёт его из `.env.example`. Повторный запуск безопасен |
| `make down` | Останавливает. Данные (конкурсы, идеи, пользователи) **сохраняются** |
| `make restart` | Остановить и запустить заново (простой 5–15 секунд) |
| `make logs` | Показать журнал приложения |
| `make help` | Список всех команд |

Данные хранятся в Docker-томе `pgdata`; `make down` его не трогает.

## 4. Как пользоваться: пошагово

Этот сценарий проходит весь конкурс от начала до финала за 10–15 минут. Удобнее держать три окна браузера: обычное (организатор), второе обычное окно или окно инкогнито (сотрудник 1) и третье (сотрудник 2): в одном браузере вход в одном окне заменяет вход в другом.

> Шаги 1–12 описаны по тексту интерфейса и проверены автоматическими тестами в браузере (см. раздел 6). Прохождение руками на Mac владельца **не проверялось** в среде агента (там нет Docker).

**Шаг 1. Войдите организатором.** Откройте http://127.0.0.1:8000, введите e-mail `organizer@example.com` и пароль `dev-only-change-me-organizer` (заглушка из `.env.example`, только для локального запуска). Нажмите «Войти». Вы увидите список конкурсов (пока пустой).

**Шаг 2. Создайте конкурс.** Нажмите «Создать конкурс», заполните «Тема», при желании «Описание», «Приём идей закрывается» и «Голосование закрывается». Чтобы не ждать, поставьте первый срок через **3 минуты** от текущего времени, второй — через **6 минут** (даты вводятся по времени вашего браузера; прошлое время и «голосование раньше приёма» сервер не примет). Нажмите «Создать конкурс», откройте конкурс по ссылке. На странице видно правило ничьей и обратный отсчёт.

**Шаг 3. Зарегистрируйте двух сотрудников.** В двух других окнах откройте http://127.0.0.1:8000, перейдите к регистрации и зарегистрируйтесь: имя любое, e-mail с доменом `example.com` (например `anna@example.com` и `boris@example.com`), пароль от 10 символов. После регистрации вход выполняется сразу. Другой домен будет отклонён (список разрешённых доменов — `ALLOWED_EMAIL_DOMAINS` в `.env`).

**Шаг 4. Подайте идеи.** Каждый сотрудник открывает конкурс из списка, вводит «Название» и «Описание», нажимает «Предложить идею». Пока приём открыт, сотрудник видит только свои идеи. Свою идею можно изменить («Сохранить») или удалить («Удалить» → подтверждение кнопкой «Да, удалить»). Организатор в это время видит на экране «Ход конкурса» число идей и список названий (без авторов).

**Шаг 5. Дождитесь голосования.** В момент, когда закончится приём, страницы сами перейдут в режим голосования (если нет — обновите страницу). Теперь каждый видит **все идеи без авторов**; свои помечены «Это ваша идея».

**Шаг 6. Проголосуйте.** Нажмите «Проголосовать» на чужой идее. За свою голосовать нельзя (кнопки нет, а сервер ответил бы отказом). На одну идею — один голос, даже если открыть две вкладки.

**Шаг 7. Отзовите голос.** Нажмите «Отозвать голос» — голос снят, можно проголосовать за другую идею. До закрытия голосования это можно делать сколько угодно.

**Шаг 8. Удалите идею во время голосования.** Автор может удалить свою идею и в голосовании: она сразу исчезает у всех вместе со своими голосами (в другом окне — в течение пары секунд, без перезагрузки).

**Шаг 9. Посмотрите экран организатора.** В окне организатора: «Идей подано», «Проголосовало» и таблица «Текущие результаты» (места и голоса, без авторов) меняются сами, когда сотрудники голосуют. Сотрудникам результаты до конца голосования не показываются.

**Шаг 10. Дождитесь финала.** Когда пройдёт срок голосования, у всех появляется «Итоги конкурса»: места, голоса и **авторы**. Победитель — идея с наибольшим числом голосов; при равенстве — поданная раньше.

**Шаг 11. Посмотрите письма.** Откройте http://127.0.0.1:8025. Письма появляются не мгновенно, а на ближайшем проходе планировщика (раз в 15 секунд):
- победителю — «Вы победили в конкурсе …»;
- авторам остальных идей — «Ваша идея не прошла: конкурс …»;
- тем, кто только голосовал, — «Итоги конкурса …».

Один человек получает одно письмо. Напоминания «Завтра закрывается приём идей / голосование» приходят, только когда до срока осталось не больше суток: при коротких сроках из шага 2 они придут сразу после создания конкурса — тем сотрудникам, у кого в этом раунде ещё нет идей (подача) или голосов (голосование).

**Шаг 12. Выход.** Кнопка «Выйти».

### Как не ждать сроки

1. **Короткие сроки руками** — как в шагах выше: 3 и 6 минут. Это обычный режим, ничего включать не надо.
2. **Режим `make e2e`** — только для автоматической проверки, не для ручной работы. Он на время прогона переключает тот же контейнер приложения в режим e2e: отдельная база `ideas_e2e` (ваши обычные данные не затрагиваются), **тестовые часы**, которые тесты двигают только вперёд, чтобы «перемотать» сроки за секунды, и отключённый лимит попыток. Вверху интерфейса в этом режиме видна плашка «E2E MODE». После прогона приложение возвращается в обычный режим dev. Пока идёт `make e2e`, рабочий сайт недоступен.

## 5. Правила простыми словами

| Вопрос | Ответ |
|---|---|
| Кто может войти? | Организатор (создаётся при первом запуске из `.env`) и сотрудники (регистрируются сами с адресом разрешённого домена) |
| Что умеет организатор | Создавать конкурсы и смотреть ход конкурса. Идеи не подаёт и не голосует |
| Во время приёма идей | Сотрудник видит только свои идеи; может подать, изменить, удалить. Организатор видит число идей и названия без авторов |
| Во время голосования | Все видят все идеи **без авторов**; за свою голосовать нельзя; голос можно отозвать; свою идею можно удалить (голоса за неё пропадут). Править идею уже нельзя |
| Результаты | До конца голосования их видит только организатор (без авторов). После — все, с авторами |
| Закрытие | Само по времени. Страница, открытая до срока, после срока ничего не примет: сервер ответит отказом |
| Один голос | На одну идею — один голос от человека, сколько бы вкладок ни было открыто |
| Ничья | Побеждает идея, поданная раньше. Если у всех 0 голосов — самая ранняя. Если идей нет — победителя нет. Правило видно на странице конкурса с самого начала |
| Напоминание | За сутки (86 400 с) до закрытия приёма — тем сотрудникам, у кого нет своих идей; за сутки до закрытия голосования — у кого нет голосов. Одно письмо на раунд. Если конкурс создан позже, напоминание уходит на ближайшем проходе, пока раунд открыт |
| Финальные письма | Победителю, авторам остальных идей и только голосовавшим — по одному письму |
| Сроки | После создания конкурса менять сроки нельзя; ошибку исправляют новым конкурсом |

## 6. Как запустить проверки

Нужны Node.js 22 и `uv` (раздел 2); для `make test-int` и `make e2e` ещё запущенный Docker. Один раз: `cd frontend && npm ci`.

| Команда | Что доказывает |
|---|---|
| `make check` | Код отформатирован, нет ошибок линтера, типы сходятся (`mypy --strict`, TypeScript), модули не нарушают границ между слоями |
| `make test-unit` | Правила конкурса (фазы на границах срока, ничья, права, письма) работают без базы и сети; интерфейс ведёт себя правильно (Vitest) |
| `make test-int` | Реальная база PostgreSQL: один голос, каскадное удаление, гонки двух запросов, миграции, API целиком, планировщик, письма. Нужен `make up`; создаёт отдельную базу `ideas_test` |
| `make test-contract` | Описание API (OpenAPI) и типы интерфейса не разошлись с кодом |
| `make e2e` | Настоящий браузер (Playwright), 8 сценариев: полный цикл с письмами в Mailpit, две вкладки, запись после срока при открытой странице, удаление идеи видно другому, экран организатора, напоминания. Один раз перед первым запуском: `cd e2e && npm ci && npx playwright install chromium` |
| `scripts/check_singleton.sh` | Контейнер приложения всегда один (повторный `make up`, параллельный запуск, второй контейнер с тем же именем, `docker compose run`) |

## 7. Если что-то не работает

| Что видите | Что делать |
|---|---|
| «Docker не запущен» / `Cannot connect to the Docker daemon` | Откройте Docker Desktop, дождитесь «Engine running», повторите `make up` |
| Порт 8000 (или 8025, 5433) занят | Закройте программу, которая его занимает (`lsof -i :8000`), или остановите старый запуск: `make down`. `make up` сообщает, чей контейнер мешает, но чужие контейнеры не удаляет |
| Страница не открывается | Подождите минуту после `make up` и откройте http://127.0.0.1:8000/api/health — должно быть `{"status":"ok"}`. Смотрите `make logs` |
| Сайт на `localhost:8000` не принимает действия (ошибка 403) | В режиме dev `localhost` и `127.0.0.1` работают оба. Если в `.env` стоит `APP_ENV=prod` или другой `PUBLIC_BASE_URL`, используйте именно тот адрес |
| Забыли пароль организатора | Смена `ORGANIZER_PASSWORD` в `.env` и перезапуск **не меняют** пароль уже созданного организатора (существующую запись приложение не трогает, чтобы не затереть пароль). Варианты: (1) укажите в `.env` другой `ORGANIZER_EMAIL` и сделайте `make restart` — создастся новый организатор с `ORGANIZER_PASSWORD` (адрес не должен принадлежать уже зарегистрированному сотруднику — иначе приложение не стартует); (2) для полного сброса **с потерей всех данных**: `docker compose down -v`, затем `make up`. Команды сброса пароля нет (не делали, см. раздел 9) |
| Письма не появляются в Mailpit | Подождите 15–30 секунд (проход планировщика); письма отправляются только после закрытия голосования или за сутки до срока. Проверьте http://127.0.0.1:8025 и `make logs` |
| Сроки «в прошлом» / «голосование раньше приёма» | Форма просит будущее время, а срок голосования должен быть позже срока приёма |
| «Слишком много попыток» при входе | Лимит 5 неудачных входов за 15 минут; подождите или перезапустите приложение (`make restart`) |
| Приложение не стартует: «БД на ревизии …» | В базе схема от другой версии кода. Вернитесь на нужную версию кода или пересоздайте данные (`docker compose down -v`, **данные будут потеряны**) |

## 10. Чем делали

- **Инструмент:** Claude Code (агент Anthropic), работающий с папкой проекта.
- **Модели:** Claude Opus 5.5 и Claude Sonnet 5.5; модель указана в футере каждого коммита.
- **Почему так:** агент сам читает и меняет файлы и запускает тесты, поэтому работоспособность доказывается прогоном тестов, а не словами; большой контекст модели позволял держать ТЗ, план и код вместе и сверять каждое решение с ТЗ. Архитектуру разбирали три субагента Claude Code (архитектура, безопасность, данные и эксплуатация) в три раунда взаимного ревью — [docs/architecture-review.md](docs/architecture-review.md). Готовность проверили два агента: принимающий (сверка с ТЗ) и разработчик.
- **Заимствования:** чужих решений и шаблонов не использовано. Каркас frontend написан вручную (`npm create vite` не запускался). Единственный генератор — `openapi-typescript`, строит `frontend/src/api/schema.gen.ts` из `frontend/openapi.json` командой `make contract`. Библиотеки и их лицензии — [CLAUDE.md §17](CLAUDE.md) (запись IC-015).

## 11. Принятые толкования ТЗ и известные ограничения

**Толкования ТЗ**

- «Сразу» и «без обновления страницы» — не дольше 2 секунд.
- «Не участвовал в раунде» — по текущему состоянию: нет своих идей в конкурсе / нет текущих голосов. Поэтому сотрудник, зарегистрировавшийся уже в окне «за сутки до срока», тоже получит напоминание; а кто отозвал все голоса или потерял их из-за удалённой идеи — тоже.
- «Все участники» финального письма — авторы текущих идей и проголосовавшие. Победителю приходит «Вы победили», авторам остальных идей — «Ваша идея не прошла», тем, кто только голосовал, — итоги конкурса.
- Организатор не подаёт идеи и не голосует. Он видит результаты без авторов до финала. **Организатор уже во время приёма идей видит названия всех идей (без авторов)**: ему нужны «текущие результаты» (ТЗ, экран организатора), а требование «чужие идеи не видны» в ТЗ относится к сотрудникам. Авторов организатор до финала не видит.
- При равенстве голосов побеждает идея, поданная раньше; при нуле голосов у всех — тоже самая ранняя.
- «Проголосовавших» на экране организатора — число разных людей с текущими голосами (отозванные голоса и голоса за удалённые идеи не считаются).

**Известные ограничения**

- Повтор правки идеи с теми же полями после дедлайна даёт 200, а не 409: запрос идемпотентен (повтор после обрыва связи не должен выглядеть ошибкой); любое изменение содержимого после дедлайна отклоняется.
- Счётчики попыток входа и регистрации хранятся в памяти процесса и сбрасываются при перезапуске; адрес клиента берётся из соединения, заголовкам прокси не верим.
- Нет подтверждения e-mail: можно зарегистрировать несколько аккаунтов на разрешённом домене.
- Письма доставляются «как минимум один раз»: при сбое в узкое окно возможен дубль.
- Один контейнер приложения: перезапуск означает простой 5–15 секунд.
- Сигналы реального времени не гарантируют доставку: при обрыве сокета страница после переподключения перечитывает данные сама. Смена фазы по времени сигналом не приходит — страница перечитывает данные в момент срока по серверному времени.
- Лимиты 20 идей на автора и 1000 на конкурс — мягкие: при одновременных записях возможно превышение на единицы.
- Часы e2e идут только вперёд; во время `make e2e` рабочее приложение недоступно, а по окончании возвращается в режим dev с прежней БД.
- Сроки конкурса после создания не меняются.
- Mailpit — заглушка: работа с реальным почтовым провайдером не проверяется.

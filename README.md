# Конкурс идей

Сервис внутренних конкурсов идей для компании: сотрудники подают идеи, потом все голосуют,
потом объявляется победитель. Конкурс идёт раундами по расписанию.
Тестовое задание, «Задание 7. Конкурс идей». Архитектура, правила разработки и все решения — в [CLAUDE.md](CLAUDE.md).

## Чем делали

Проект делается вместе с AI-агентом **Claude Code** на модели **Claude Opus 5.5**. Агент работает прямо
с папкой проекта и запускает тесты, поэтому работоспособность будет доказываться прогоном тестов, а большой контекст
модели позволяет сверять каждое решение с ТЗ. Архитектуру разбирали три субагента Claude Code
(архитектура, безопасность, данные и эксплуатация) в три раунда взаимного ревью — [docs/architecture-review.md](docs/architecture-review.md).

## Требования

План (будет проверено на этапе каркаса): Docker Desktop с Compose ≥ 2.20. Для разработки без контейнера
приложения — `uv` (Python 3.12) и Node.js 22 LTS. Подробно — [CLAUDE.md, §11](CLAUDE.md).

## Запуск

План: `make up`, затем `http://127.0.0.1:8000` (приложение) и `http://127.0.0.1:8025` (письма в Mailpit).
Команды ещё не существуют — появятся на этапе каркаса. Эксплуатация и диагностика — [docs/runbook.md](docs/runbook.md).

## Принятые толкования ТЗ

- «Сразу» и «без обновления страницы» — не дольше 2 секунд.
- «Не участвовал в раунде» — по текущему состоянию: нет своих идей в конкурсе / нет текущих голосов.
- «Все участники» финального письма — авторы текущих идей и проголосовавшие.
- Организатор не подаёт идеи и не голосует; до финала видит результаты без авторов.
- При равенстве голосов побеждает идея, поданная раньше; при нуле голосов у всех — тоже самая ранняя.

## Известные ограничения (честно)

- Нет подтверждения e-mail: можно зарегистрировать несколько аккаунтов на разрешённом домене.
- Письма доставляются «как минимум один раз»: при сбое в узкое окно возможен дубль письма.
- Один контейнер приложения: перезапуск означает простой 5–15 секунд.
- Mailpit — заглушка: работа с реальным почтовым провайдером не проверяется.

# Runbook: запуск, эксплуатация, диагностика, восстановление

> **Статус: план.** Скрипты и `Makefile` появятся на этапе каркаса. Ни одна команда ниже ещё не запускалась.
> Обязательные правила — `CLAUDE.md` §11–§13; здесь подробности для оператора.

## 1. Первый запуск

| Шаг | Команда | Ожидаемый результат |
|---|---|---|
| 1 | Установить Docker Desktop, запустить его | `docker info` без ошибок |
| 2 | `make up` | Создан `.env` из `.env.example`; собран образ; подняты `db`, `mailpit`, `app`; лаунчер `python -m app.core.launcher` взял advisory lock и применил миграции; создан организатор; в выводе URL `http://127.0.0.1:8000` |
| 3 | Открыть `http://127.0.0.1:8000`, войти организатором из `.env` | Список конкурсов |
| 4 | Открыть `http://127.0.0.1:8025` | Веб-интерфейс Mailpit (письма приложения) |

Для разработки без контейнера приложения: `uv sync` в `backend/`, `npm ci` в `frontend/`,
`npm run dev` (Vite на `:5173` с прокси на `:8000`). Контейнер `app` при этом должен работать или
быть остановлен целиком — второй сервер против той же БД не стартует (advisory lock).

## 2. Обычная работа

| Задача | Команда | Примечание |
|---|---|---|
| Запустить / применить изменения | `make up` | Идемпотентно; пересоздаёт `app` при изменении конфигурации; всегда возвращает режим dev |
| Остановить | `make down` | Данные БД сохраняются (volume не удаляется) |
| Перезапустить | `make restart` | Простой 5–15 с; не делать в последний час перед дедлайном |
| Логи | `make logs` | JSON; фильтр по `request_id` из ответа об ошибке |
| Состояние | `make status` | Контейнеры по label, режим, outbox, лаг планировщика, ближайший дедлайн |
| Миграции вручную | `make migrate` | Через `exec`, не `run` |
| CLI | `make cli ARGS="…"` | `create-organizer`, `reset-password <email>`, `revoke-sessions --all`, `status` |
| Консоль БД | `make psql` | |

Запрещено: `docker compose run` для задач, `docker compose down -v`, `docker volume prune` в обычной работе.

## 3. Проверка инварианта одного контейнера

`scripts/check_singleton.sh` выполняет сценарий `CLAUDE.md` §12.4 и печатает число контейнеров
приложения после каждого шага. Ожидаемо: везде 1, после `make down` — 0, volume на месте.

Ручная проверка в любой момент:

```sh
docker ps -a --filter label=org.ideas-competition.role=app \
  --format '{{.ID}} {{.Names}} {{.Label "com.docker.compose.project"}} {{.Status}}'
```

Если найден лишний контейнер (например, `…-app-run-…` или другой project): скрипты его **не удаляют**.
Проверьте, чей он, и остановите сами: `docker stop <ID> && docker rm <ID>`.

## 4. Диагностика типичных ошибок

| Симптом | Причина | Действие |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен | Запустить Docker Desktop, повторить `make up` |
| `port is already allocated` (8000/8025/5433) | Порт занят другим процессом | `lsof -i :8000`; остановить процесс (порты в этом объёме фиксированы, `CLAUDE.md` §11.1) |
| `Conflict. The container name "/ideas-competition-app" is already in use` | Контейнер приложения уже есть (другой project или клон) | `make status`; остановить чужой контейнер вручную |
| `Другой экземпляр приложения уже подключён к этой БД` | Работает второй сервер (контейнер, локальный uvicorn, IDE) | Сообщение содержит адрес из `pg_stat_activity`; остановить лишний процесс |
| `База данных не готова за 60 с` | `db` не стартовал или нет места на диске | `docker compose logs db`; проверить место |
| `Неверная конфигурация: …` (код 2) | Не задана или неверна переменная окружения | Сверить `.env` с `.env.example`; значения секретов в сообщении не печатаются |
| `БД на ревизии X, приложению известна Y` | Запущена более старая версия кода, чем схема БД | Вернуться на актуальный коммит или восстановить БД из бэкапа той версии |
| `/api/health` = 503 | БД недоступна, lock потерян или схема несовместима | `make logs`, искать `health` |
| Письма не приходят | Mailpit не запущен или SMTP-ошибки | `make status` (outbox `failed`/`pending`), `last_error`; перезапустить `mailpit` |
| Лаг планировщика > 2 мин | Тики падают или БД медленная | `make logs`, фильтр `job` |
| Красная плашка «E2E MODE» в UI | Прерванный `make e2e` | `make up` (вернёт dev; dev-данные не тронуты) |
| 429 при входе | Сработал лимит попыток | Подождать `Retry-After` |

## 5. Бэкап и восстановление

| Задача | Команда | Результат |
|---|---|---|
| Бэкап | `make backup` | `backups/ideas-<UTC>.dump` (`pg_dump -Fc`), права 600 |
| Проверить бэкап | `make restore-check FILE=backups/…` | Восстановление во временную БД `ideas_restorecheck`, сверка ревизии схемы и числа строк, удаление временной БД |
| Восстановить | `make restore FILE=backups/…` | Остановка `app` → пересоздание БД → `pg_restore` → `make up`. Требует ввода имени проекта |

Бэкап считается рабочим только после успешного `restore-check`. Храним 7 последних локальных бэкапов.
В дампе есть персональные данные и авторство идей — не передавать и не коммитить (`backups/` в `.gitignore`).

## 6. Неудачная миграция или выкладка

- Запуск контейнера — python-лаунчер `app/core/launcher.py` (не shell-entrypoint): advisory lock → миграции → uvicorn в том же процессе, чтобы lock держался всё время работы сервера (CLAUDE.md §7.4).
- Миграция упала при старте → контейнер не стартует, схема остаётся на последней успешной ревизии (`transaction_per_migration`). Исправить миграцию, `make up`.
- Нужен откат приложения → вернуть предыдущий коммит/образ. После expand-миграции старая версия работает на новой схеме. После contract-миграции — только восстановление из бэкапа.
- Порча данных → `make restore` из последнего проверенного бэкапа.

## 7. План выкладки в прод (не реализуется в этом объёме)

1. `make backup` + `restore-check`.
2. Сборка образа с тегом git sha.
3. Остановка `app` (простой).
4. Миграции (только expand).
5. Старт, smoke: `/api/health`, вход организатора, `GET /api/contests`.
6. Неудача → предыдущий образ; порча данных → восстановление.
7. Не выкладывать в последний час перед любым дедлайном.

Для прода дополнительно потребуются: https и `__Host-` cookie, SSO вместо паролей, реальный SMTP,
сбор метрик и оповещения, решение о флаге запуска при более новой схеме.

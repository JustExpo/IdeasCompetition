## Оси §6.5
- **Безопасность.** CSRF/CSWSH: проверка `Origin` остаётся белым списком. Двойник — тот же сервис на петле; другой порт, схема, поддомен отклоняются (тесты). В prod двойника нет; для не-петлевого `PUBLIC_BASE_URL` (например `http://ideas.corp:8000`) он не строится. Cookie `sid` привязана к хосту, поэтому вход на `localhost` и на `127.0.0.1` — независимые сессии (ожидаемо). Секреты в README — только заглушки из `.env.example`, помечены «dev only».
- **Структура.** Логика в `core/config.py` рядом с `allowed_origins`; потребители (`main.py`, `realtime/controller/router.py`) не менялись. Комментарий объясняет «почему».
- **Архитектура.** Новых зависимостей, модулей и слоёв нет; Р1–Р14 не затронуты; `lint-imports` зелёный.
- **Корректность.** Границы: оба направления двойника, порт, схема, поддомен, отсутствие порта, prod, e2e. Найдено при проверке README: смена `ORGANIZER_PASSWORD` в `.env` НЕ меняет пароль существующего организатора (`auth/service/organizer.py`), хотя владелец предполагал обратное; в README описан честный обход (другой `ORGANIZER_EMAIL` или `docker compose down -v` с потерей данных). Поведение кода не менялось (так решено в IC-007: пароль, сменённый оператором, не затирается); команда сброса пароля остаётся в «Следующим заходом».

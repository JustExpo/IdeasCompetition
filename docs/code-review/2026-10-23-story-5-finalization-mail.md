## Безопасность
- Письма — plain text, заголовки через `EmailMessage`; тексты идей в письма не попадают, только тема конкурса и название победившей идеи (после финала авторство публично по ТЗ).
- В логах нет адресов, тел писем и текстов идей: `job_failed`, `tick_failed` пишут только имя задачи и тип ошибки; `last_error` в outbox хранит класс ошибки SMTP без адреса.
- SQL только с параметрами; новых зависимостей нет.
- Одно письмо на человека: нельзя получить «победили» и «не прошла» одновременно.

## Корректность
- Финализация: однократна при повторах и параллельных тиках; гонка «голос на границе ‖ финализация» (FOR SHARE против FOR UPDATE) — голос либо в итоге, либо 409.
- Outbox: создание exactly-once (повтор не дублирует), аренда, backoff с верхней границей (экспонента ограничена, `timedelta` не переполняется), 5xx → `failed`, `not_after` → `expired`, 8 попыток.
- Напоминания: границы `deadline−24h−1µs / deadline−24h / deadline−1µs / deadline`, два тика и параллельные тики — одно письмо.
- Остановка: тик, переживший отсрочку, отменяется, блокировка тика не остаётся занятой.

## Найденное и исправленное по ходу
- Тик держал транзакцию дольше `idle_in_transaction_session_timeout` (30 с) — добавлен `SET LOCAL … = 0`.
- `retry_delay(50)` переполнял `timedelta` — экспонента ограничена.
- Нестабильный тест ничьей: `FrozenClock` давал всем идеям одно `submitted_at`; помощник сдвигает часы на 1 с на идею.
- Ожидание в тесте «нет напоминания на дедлайне подачи» было неверным: на этой границе законно уходит напоминание раунда голосования.
- Тест остановки зависал из-за ошибки в самом тесте (завершающий `run_tick()` снова запускал «застрявшую» задачу); исправлено, `stop()` менять не пришлось.

## Известные ограничения
- Письма уходят на ближайшем тике (до `SCHEDULER_INTERVAL_S`), а не сразу после commit.

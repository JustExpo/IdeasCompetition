## Найдено и исправлено

1. Первый вариант контракта `core-is-infrastructure` запрещал `core` импортировать и `app.common`; но `core/http_errors.py` (IC-004) обязан использовать `AppError` → `common` из запрета убран, зафиксировано в §4.2 и §17.
2. `type: ignore[call-arg]` на `Settings()` оказались лишними (плагин pydantic в mypy) → убраны.
3. Тест «пустая переменная» сначала проверял имя поля в неверном регистре → исправлен.
4. Строка с паролем-заглушкой вызывала `S105` → точечный `noqa` с пояснением; в тестах `S105/S106` отключены глобально (фиктивные значения).

## Осталось и почему

- `EXAMPLE_ORGANIZER_PASSWORD` — константа в коде: это публичная заглушка из `.env.example`, не секрет; тест сверяет её с файлом.
- Ключи `title`/`description` маскируются по имени во всех записях: если позже понадобится логировать название конкурса, придётся назвать поле иначе (например `contest_topic`).
- Настройка логов uvicorn (чтобы его записи шли через ту же цепочку) — в IC-006 при сборке запуска; здесь корректность для стандартного `logging` проверена на логгере `uvicorn.error`.
- Middleware `request_id` и проверка формата `X-Request-ID` — IC-004; здесь только `bind_log_context`.
- `.env.example` содержит только dev-заглушки; `make up` создаст из него `.env` в IC-006.

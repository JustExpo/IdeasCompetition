## Найдено и исправлено

1. Выброс ошибки из `receive` при чтении тела FastAPI превращал в 400 («error parsing the body»): тест на chunked-тело без `Content-Length` показал 400 вместо 413. Ответ приложения теперь подменяется на 413, пока оно не отправило свой.
2. `S608` в тесте (SQL-подобная строка в исключении — намеренно, проверяем, что она не утекает) → точечный `noqa`.
3. Утверждения `assert` в обработчиках для сужения типа заменены на `cast` (нет `assert` в боевом коде).
4. `require()` возвращал `Any` → явный тип `params.Depends`.

## Осталось и почему

- Пока нет сессий (IC-007), любая политика кроме `PUBLIC` отвечает 401: это сознательно (default deny); роли и 403 по политике подключаются в IC-007.
- `Retry-After` для 429/503 не реализован: таких ответов ещё нет (IC-007 — лимит попыток, IC-005 — недоступность БД).
- CSP и статика SPA — IC-015; проверка `Origin` для WebSocket — IC-024.
- Пока `Origin` без порта по умолчанию (`https://host` и `https://host:443`) считается разным: сравнение точное по строке, как в `allowed_origins`; браузеры шлют каноничный вид.
- Запись о запросе пишется на уровне INFO в том числе для `/api/health` (healthcheck Docker): при шуме уровень будет снижен в IC-006.
- Api-тесты лежат в `tests/unit/core`, потому что БД не нужна и CI пока запускает только `pytest -m unit`.

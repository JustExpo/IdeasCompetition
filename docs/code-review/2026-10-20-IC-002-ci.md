## Найдено и исправлено

1. Ruff в `tests/` (отдельный `ruff.toml`) считал `tests` внешним пакетом и требовал другой порядок импортов → `known-first-party = ["app", "tests"]` в общем конфиге.
2. Первая версия хука маркера `unit` превышала длину строки → строка сокращена.

3. Первый прогон CI: `gitleaks-action` упал с 403 «Resource not accessible by integration» (чтение коммитов PR) → job `security` получил `pull-requests: read`, остальные права остались `contents: read`.

## Осталось и почему

- **Красный CI на PR с нарушением не прогонялся:** для этого нужен отдельный тестовый PR с нарушением. Локально контракт возвращает ненулевой код, который роняет шаг CI; прогон на GitHub — по решению владельца (можно показать на первом PR с намеренной ошибкой).
- **Зелёный CI:** первый прогон на GitHub нашёл ошибку прав gitleaks (см. выше), исправлено в том же коммите.
- **Покрытие:** `pytest --cov` показывает 87 %; у `app/vote/model` нет тестов. Порог ≥ 95 % для `app/*/model` включается в IC-030 (CLAUDE.md §10.3), тесты голоса — в IC-013.
- `ruff` banned-api без исключения для `app/core/clock.py`: пакета `core` ещё нет, исключение добавляется в IC-003.
- Версии действий GitHub (`@v4`, `@v6`, `@v2`) закреплены по мажору, а не по SHA: для учебного прототипа принято, для продакшена нужен pin по SHA.

# Самопроверка: IC-009 — политики доступа по фазам и ролям

Дата: 2026-10-21 · Изменение: `backend/app/{contest,idea,vote,result}/model/policy.py`, `common/model/actor.py`, `auth/model`, `user/model`, `auth/service/sessions.py`, `tests/unit/test_policies.py`.

## Что проверено

| Ось | Результат |
|---|---|
| Безопасность | Права проверяются только по роли, фазе и авторству, без I/O; чужая идея в приёме невидима (404 вместо 403), организатор до финала не видит ни идей в приёме, ни авторов; организатор не подаёт, не голосует, не правит; отключённый пользователь получает отказ везде (вторая преграда после `resolve_actor`); порядок ошибок 401 → 404 → 403 → 409 закреплён тестами |
| Структура | Политики в `<модуль>/model/policy.py` (§4.4), публичное API через `__init__`; имена по §6.2: `can_*` возвращают `bool` и не бросают, `ensure_*` бросают ошибку модуля |
| Архитектура | `Actor` и `UserRole` перенесены в `common.model`, иначе `contest` и `idea` пришлось бы импортировать `auth`/`user` (один уровень графа); `auth.model` и `user.model` реэкспортируют их, чужие импорты не менялись; `model` не импортирует исключения других модулей (404 видимости для голоса проверяет сервис); 17 контрактов import-linter зелёные |
| Корректность | Таблицы истинности: фаза × роль × свой/чужой × активен для подачи, голоса, отзыва, видимости, правки, удаления, авторов и итогов; границы `d−1µs / d / d+1µs` обоих дедлайнов через `ContestSchedule.phase_at`; порядок ошибок в каждом `ensure_*`; ветки политик и `actor.py` покрыты на 100 % |

## Найдено и исправлено

1. Спецификация требует политики в `contest.model` и `idea.model`, но `Actor` жил в `auth.model`, недоступном для этих модулей по графу §4.2 — перенесён в `common.model` вместе с `UserRole`.
2. У `Actor` не было признака активности, а спецификация требует учёта неактивного пользователя — добавлено `is_active`; `resolve_actor` передаёт его явно.
3. Для сценариев §7.2 не хватало отзыва голоса, итогов и подачи — добавлены `ensure_can_withdraw_vote`, `ensure_can_view_results`, `ensure_can_submit_idea`.

## Осталось и почему

- Политики адресатов событий — IC-024 (вне объёма).
- `is_active=True` по умолчанию: тесты и код, создающие `Actor` вручную, должны задавать его явно, если нужен отключённый пользователь; в рантайме `Actor` всегда строит `resolve_actor`.
- Видимость идеи для голосования (404) остаётся за сервисом IC-012: политика голоса её не проверяет, это записано в докстринге модуля и в спецификации.

## Найдено и исправлено

1. Штатный `uvicorn.Server.capture_signals` после остановки повторно посылает себе пойманный SIGTERM, и процесс умирал мимо `finally` лаунчера (блокировка снималась лишь закрытием сокета, `dispose` не вызывался). Переопределён `capture_signals` в `DrainingServer` без повторной отправки.
2. Health должен отвечать 503 уже в момент SIGTERM, до остановки приёма: флаг `draining` ставится в `handle_exit`.
3. asyncpg без типов — override mypy `ignore_missing_imports` только для него.
4. Запрет `sleep` в тестах: ожидание освобождения — через `asyncio.wait`/`Event`; опрос готовности порта — через таймаут по `Event`, события для перезахвата — колбэк `on_reacquired`.

## Осталось и почему

- Сборка образа, `make up`, повторный `make up` с тем же ID и ровно один контейнер в контейнере агента не проверены (нет демона Docker): проверяет job `docker` в CI; `make up` на Mac проверяет владелец (критерий приёмки остаётся открытым).
- `scripts/up.sh` не предупреждает о ближайшем дедлайне: таблицы конкурсов ещё нет (IC-010/IC-020). `make cli` указывает на `app.cli` из IC-007; `make status`, `backup`, `restore*`, `destroy` не создаются (объём прототипа).
- Docker-образ без SPA: стадия node добавится в IC-015. Образ `axllent/mailpit:v1.21` не закреплён по digest.
- Потеря соединения монитора с БД короче 10 с может остаться незамеченной: пока соединение живо, блокировка за нами; если оно оборвалось и блокировку успели взять, `verify` и health покажут потерю при следующей проверке (≤ 10 с).

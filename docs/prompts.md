- стабильную идентичность Compose-проекта;
- одну реплику приложения;
- повторный запуск без появления дубликатов;
- защиту от одновременного запуска двумя процессами;
- обнаружение лишних экземпляров без удаления чужих ресурсов;
- очистку временных контейнеров после успеха и ошибки.

Не запускай второй экземпляр приложения через одноразовые
команды, если задача может выполняться в существующем.

Одних project name и количества реплик недостаточно
для обещания глобальной гарантии: учти альтернативные
точки запуска и область действия выбранного механизма.

Добавь проверку инварианта:
первый запуск → повторный запуск → конкурентный запуск →
проверка количества работающих экземпляров → остановка.

Учти, что при строгом ограничении одной реплики
перезапуск и обновление могут сопровождаться простоем.

Удаление persistent volumes не должно быть частью
обычного перезапуска или очистки.

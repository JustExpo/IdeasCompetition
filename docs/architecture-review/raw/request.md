# Запрос владельца (сокращённо до требований к содержанию)

Итог — CLAUDE.md: архитектура, структура проекта, правила кода, стратегия тестирования, БД, безопасность, запуск, эксплуатация, критерии готовности. Только проектирование, без реализации. Разделять фактическое / предлагаемое / изменения для перехода. Для каждого существенного решения: «решение → причина → альтернативы → ограничения → проверка». Критерии: корректность, безопасность, проверяемость, сложность, стоимость эксплуатации. Минимальная архитектура; микросервисы, очереди, кэш, CQRS, event sourcing — только при конкретной необходимости. N/A с причиной для неприменимого.

Разделы:
3. Принципы архитектуры: границы модулей и направление зависимостей; бизнес-правила отдельно от транспорта/хранения/интеграций; точки входа и владельцы побочных эффектов; без циклов; дерево каталогов; схема компонентов и потоков; обоснование каждой инфраструктурной зависимости.
4. Code style: имена функций = действие+предмет; предикаты и побочные эффекты различимы; единая терминология (код/API/доки); явные зависимости; типы выражают допустимые состояния; ошибки явно, без молчаливого подавления; технические → понятные ошибки приложения; комментарии объясняют причины; абстракции по подтверждённой необходимости; секреты не в коде/логах. Formatter, linter, type checker и команды. Примеры хороших названий и размещения логики.
5. БД: сущности, связи, ID, владельцы данных; уникальность, FK, индексы; границы транзакций и согласованность; конкурентные обновления, потерянные изменения, дедлоки; повторная запись и дубли запросов; пулы, таймауты, недоступность БД; миграции и совместимость версий (откат приложения не всегда допускает откат миграции); безопасное заполнение данных; бэкап и проверка восстановления; удаление, сроки хранения, чувствительные данные; часовые пояса, точность, NULL-семантика.
6. API и интеграции: контракты запросов/ответов/ошибок; валидация, размеры, форматы; статусы без утечки деталей; пагинация/сортировка/фильтрация; совместимость контрактов; идемпотентность; таймауты, отмена, ограниченные retries (с учётом безопасности операции, бюджета времени, риска повторного эффекта); частичный успех и неизвестный результат. Фоновые задачи/webhook: повторная доставка, порядок, подлинность, дедупликация, восстановление, завершение.
7. AuthN/AuthZ/безопасность: механизм входа и почему; жизненный цикл сессий; истечение, отзыв, выход; регистрация, восстановление, MFA (если нужно); роли, разрешения, проверка доступа к конкретному объекту; изоляция; изменение прав в активной сессии; защита от перебора и злоупотреблений; секреты и ротация. Default deny, проверки на сервере. Риски: инъекции, XSS, CSRF, SSRF, загрузка файлов, утечки, обход объектной авторизации. Без самописной криптографии.
8. Тестирование: Unit (без сети/БД, управляемые часы/случайность), Integration (реальные адаптеры, SQL, транзакции, миграции, изолированная инфраструктура), Contract (сериализация, версионированный контракт, источник и версия), E2E (критические сценарии, изолированно). Никаких реальных внешних сервисов и рабочих секретов. API-моки: успех, ошибки, таймауты, retries, некорректные/неполные ответы; не доказательство живого провайдера. Каждая функция с бизнес-логикой — проверяемое поведение, границы и ошибки; через публичный интерфейс допустимо. Покрытие критических ветвей; процент — вспомогательно. Регрессионные тесты на баги. Без зависимости от порядка и sleep. Команды запуска наборов.
9. Docker: ИНВАРИАНТ — на одном Docker-хосте не более одного контейнера приложения этого проекта. Область действия ограничения; БД и инфраструктура — отдельные контейнеры, не реплики. Спроектировать: единую команду запуска; стабильную идентичность Compose-проекта; одну реплику; повторный запуск без дубликатов; защиту от одновременного запуска двумя процессами; обнаружение лишних экземпляров без удаления чужих ресурсов; очистку временных контейнеров после успеха и ошибки. Не запускать второй экземпляр через одноразовые команды (docker compose run), если задача выполнима в существующем (exec). project name и replicas недостаточно для глобальной гарантии — учесть альтернативные точки запуска. Проверка: первый запуск → повторный → конкурентный → подсчёт экземпляров → остановка. Простой при перезапуске. Удаление volumes не входит в обычный перезапуск/очистку.
10. Конфигурация и жизненный цикл: версии инструментов, воспроизводимая установка; обязательные env и безопасный .env.example; валидация конфигурации при старте; dev/test/prod; первый запуск, миграции, тестовые данные; запуск/остановка/перезапуск; health, readiness, graceful shutdown; завершение активных запросов и закрытие ресурсов; диагностика типичных ошибок. Для каждой команды — назначение и ожидаемый результат; отделять существующие от предлагаемых; не утверждать, что команда проверена.
11. Наблюдаемость, CI/CD, восстановление: структурированные логи, correlation id; метрики ошибок/задержек/ресурсов; маскирование; оповещения и действия оператора; лимиты CPU/памяти/соединений/очередей. CI: формат, lint, типы, тесты, сборка, контракты, миграции, проверка зависимостей. Порядок выкладки, smoke, действия при неудаче, восстановление данных.
12. Матрица пограничных случаев: Сценарий | Ожидаемое поведение | Защитный механизм | Уровень теста | Остаточный риск. Обязательно: пустые/отсутствующие/некорректные/слишком большие данные; Unicode, даты, TZ, числовые границы; отсутствующая/удалённая запись; нарушение уникальности; два одновременных изменения; повтор после таймаута; истёкшая сессия, недостаточные права; доступ к чужим данным; недоступность/медленная зависимость; неверный формат внешнего API; частичная операция; сбой между записью и внешним действием; остановка во время запроса/задачи; повторный и конкурентный запуск приложения; нехватка памяти/места/соединений; неудачная миграция, несовместимая схема. Плюс доменные сценарии.
13. Definition of Done: границы и style; права и ошибки; покрыты изменённые сценарии и границы; тесты без внешних сервисов; совместимость и миграции; обязательные проверки проходят; документация соответствует; нет необоснованных новых сервисов и зависимостей.

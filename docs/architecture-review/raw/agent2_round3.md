## К4 — правка идеи после закрытия приёма

- **Вход.** Форма правки открыта в 11:55, получена `version=3`. «Сохранить» нажато в 12:00:01, а `submission_deadline` = 12:00.
- **Как ломается.** `UPDATE … WHERE id AND author AND version=3` находит строку: версия совпадает. Фаза по К4 проверяется только в ветке «0 строк», поэтому правка проходит.
- **Последствие.** Нарушено П2: правка принята после закрытия приёма, хотя страница была открыта заранее. Ровно этот сценарий ТЗ требует отклонять.
- **Правка.** Порядок такой же, как в К3 и К18:
  1. `SELECT contest FOR SHARE`;
  2. `SELECT idea FOR UPDATE`. Нет записи или автор не совпадает → 404;
  3. присланные поля равны текущим → 200 (повтор с неизвестным результатом, проверка до фазы);
  4. `now = clock.now()`, фаза ≠ `submission` → 409 `submission_closed`;
  5. `version ≠ :v` → 409 `stale_version`;
  6. `UPDATE … SET version = version + 1`.

  Альтернатива: оставить оптимистичный UPDATE, но добавить в WHERE `AND :now < (SELECT submission_deadline FROM contests WHERE id = :cid)`, где `now` прочитано после `FOR SHARE` конкурса.
- **Проверка.** Integration с FakeClock:
  - правка с верной версией при `now == submission_deadline` → 409 `submission_closed`;
  - повтор уже применённой правки после дедлайна → 200.

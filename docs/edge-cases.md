# Матрица пограничных случаев

Сводная матрица по итогам трёх проходов анализа (архитектура, безопасность, данные и эксплуатация)
и решений координатора. Ссылки на решения — `CLAUDE.md`. Уровни тестов: **unit** (без БД и сети),
**int** (integration, реальный PostgreSQL), **contract** (наборы ключей и схемы ответов), **e2e**
(Playwright, два браузерных контекста), **ops** (сценарий `scripts/check_singleton.sh` / ручная проверка).

> Статус: **проект**. Код и тесты ещё не написаны; колонка «Тест» — какой тест обязан появиться.
> Матрица не претендует на исчерпывающий охват неизвестных рисков.

| Невалидный JSON | 400 `malformed_json` | обработчик ошибок | int | — |
| Лишнее поле во входе (например `author_id`) | 422 | `extra="forbid"` | contract | — |
| NUL `\x00` в тексте | 422, не 500 | валидатор до БД (PostgreSQL `text` не принимает NUL) | int | — |
| Одиночный суррогат `\ud800` в JSON | 422 | валидатор кодировки | int | — |

## 2. Время и фазы

| Сценарий | Ожидаемое поведение | Защитный механизм | Тест | Остаточный риск |
|---|---|---|---|---|
| Запись ровно в `now == deadline` | Отклонена (раунд открыт, пока `now < deadline`) | `compute_phase` со строгим `<` | unit (`d−1µs`, `d`, `d+1µs`) | — |
| Страница открыта до дедлайна, отправка после (П2) | 409 `submission_closed` / `voting_closed`, понятный текст | проверка фазы на сервере в транзакции | int, e2e | — |
| Запрос отправлен до дедлайна, обработан после | Отклонён: момент приёма = время обработки сервером | `now` читается после блокировки конкурса | int (FakeClock) | Пользователь с медленной сетью; UI предупреждает по серверному смещению |
| Голос на границе ‖ финализация | Голос либо попадает в итог, либо 409; итог в письмах совпадает с БД | `FOR SHARE` у записи, `FOR UPDATE` у финализации | int (два соединения, барьер) | — |
| Повтор транзакции после дедлока у дедлайна | Повтор читает `now` заново → 409, если дедлайн прошёл | `run_in_transaction` | int (FakeClock сдвигается между попытками) | — |
| Часы браузера пользователя сбиты | Таймеры и кнопки по серверному времени | `server_time` в ответах, `serverTime.ts` | unit (TS) | — |
| Планировщик остановлен в момент дедлайна | Фаза всё равно сменилась (вычисляется); письма уйдут на первом тике после старта | вычисляемая фаза; первый тик при старте | int | Задержка писем на время простоя |

| Сценарий | Ожидаемое поведение | Защитный механизм | Тест | Остаточный риск |
|---|---|---|---|---|

## 6. Запуск, миграции, инвариант одного контейнера

| Сценарий | Ожидаемое поведение | Защитный механизм | Тест | Остаточный риск |
|---|---|---|---|---|
| Повторный `make up` | No-op, тот же контейнер | идемпотентность Compose | ops | — |
| Два `make up` параллельно | Один контейнер; второй — no-op или понятная ошибка Compose | `container_name` | ops | Неочевидный текст ошибки Compose |
| `docker compose -p other up` / `--scale app=2` | Отказ: имя контейнера занято | `container_name` | ops | — |
| `docker compose run app …` | Контейнер создаётся, но сервер в нём не стартует и миграции не применяет (lock берётся первым) | session advisory lock в БД | ops | Без `--rm` контейнер остаётся до ручного удаления; правило запрещает `run` |
| Локальный uvicorn / IDE при работающем контейнере | Отказ старта: «другой экземпляр подключён к этой БД» | advisory lock | ops | Против другой БД — вне гарантии |
| Ручной `docker run` против другой БД | Не обнаруживается | — | — | Вне области гарантии |
| Рестарт БД при работающем приложении | Lock перезахватывается или приложение завершается | проверка соединения каждые 10 с | ручная | Окно ≤ 10 с |
| Миграция упала | Контейнер не стартует, схема на последней успешной ревизии | `transaction_per_migration` | CI | Частично применённая серия миграций |
| Откат приложения после expand-миграции | Старая версия работает на новой схеме | правило expand/contract | CI | Contract-миграции требуют восстановления из бэкапа |
| Бэкап не восстанавливается | Обнаруживается в CI | `restore-check` | CI | Разные версии `pg_dump` |
| E2E прерван SIGKILL | Контейнер остался в e2e-режиме, dev-данные не тронуты; `make up` возвращает dev | отдельная БД `ideas_e2e`, плашка в UI | ops | — |
